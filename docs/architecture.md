# Architecture

The trusted interface is bundled Svelte with Journeys, Account and Settings. Revision 2 adds native online guest stop lookup, journey search, result legs and departure boards through a typed Rust Ubian adapter. No app-operated backend, account session, SQLite cache or offline router is required for guest timetables. A separate native account client now owns authenticated cookies and a small profile cache. Optional connection-detail enrichment is checked against the selected trip and rejected when its dates disagree.

| Boundary                    | Implementation                                                | Available actions                                                                                                                                |
| --------------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| Bundled main view           | `src/`, `src-tauri/`                                          | Local navigation/preferences, native login/account status, guest timetables, fixed recovery/support entry points, appearance and storage actions |
| Rust coordinator            | `plugins/android-platform/src/lib.rs`                         | Validate bundled caller, typed destination/language/appearance/query; dispatch native platform work                                              |
| Online timetables           | `crates/journey-core/src/timetable.rs`, `Timetables.svelte`   | Fixed-origin anonymous HTTP, typed queries/results/detail/departures, validation, bounds, cancellation and shared throttling                     |
| Provider website            | Native `ProviderActivity`, newly constructed platform WebView | Restricted website navigation/resources; no application bridge                                                                                   |
| Public Keystore probe       | `ProbeVault.kt`, background worker                            | Public test records with a non-authentication-bound key; status booleans only                                                                    |
| Account-storage preparation | `vault.rs`, `VaultRecord.kt`, `AccountVault.kt`               | Internal synthetic availability/save-update/unlock-verify/delete contracts; only status is exposed to the frontend                               |
| Shared policy               | `policy/network-policy.json`, `crates/journey-core`           | Versioned origin/optional-request rules with immutable native evaluation                                                                         |

The main window has a navigation guard. Its capability names only `main`, is local-only and grants narrowly scoped plugin commands. Rust checks the calling view label and bundled origin again. Debug builds also permit the configured frontend development origin. Production loads bundled assets with a CSP that disallows frames, remote scripts and form submissions. No generic URL fetch, secret read, arbitrary script or filesystem command is exposed. `withGlobalTauri` is never injected into the provider WebView.

`ProviderActivity` is not exported. Rust and Kotlin independently accept only login and support as fixed provider destinations; the former journeys destination is removed. The Activity constructs an ordinary WebView rather than reusing Tauri's bridged view. External HTTPS navigation requires a user gesture and a native destination confirmation. Unknown schemes, arbitrary intents, nonstandard ports, ambiguous authorities, certificate errors and automatic external redirects are refused. Uploads, downloads, popups and location remain unavailable pending verification. App-owned native controls support `sk`, `en` and `uk`; Ukrainian uses the Slovak provider page without claiming a provider translation.

Preferences retain their stable storage key and System/Slovak defaults. Validation accepts `uk` and the distinct `black` theme without invalidating older saved preferences. A bundled blocking script sets the initial palette/language before mounting; Svelte applies contrast-adjusted accent tokens. Black base/navigation surfaces are `#000000`; explicit Black does not follow device theme changes. System-bar matching is a typed native action. Navigation-only CSS suppresses WebView tap highlighting and text selection, with selected/pressed/accent states and visible keyboard focus retained. Android interaction behavior still needs device evidence.

`Timetables.svelte` owns in-memory selections, filters, results, departures and detail navigation. Editing a stop name invalidates its selection. Stop lookup is debounced; independent request IDs cancel native network futures, while generation checks reject late completions in the UI. Opening detail preserves the results and restores scroll on return. Provider names render as text, and there is no automatic website or fixture fallback.

`TimetableClient` is shared as process-owned Tauri state. It accepts only the four observed paths on `https://www.ubian.sk`, sends form-encoded nested stop fields, uses verified TLS with the maintained Mozilla root store and rejects redirects. It bounds bodies and collections, validates response types and timestamps, applies deadlines and shared rate/backoff limits, and does not retry automatically. It does not load WebView cookies, credentials or provider scripts. Detail commands use tokens issued for recent results rather than accepting arbitrary provider parameters. Request dates use `Europe/Bratislava`, independently of device timezone; missing spring times are rejected and the repeated autumn hour has an explicit occurrence choice. Offset-bearing responses preserve their instants. No absent update or zero delay is promoted into a realtime claim. See [provider discovery](provider-discovery.md) and [verification](revision-2-verification.md).

The native account client accepts a local email/password form through typed commands, submits the observed HTTPS `/login` form, and independently verifies `/user/profile` against the expected login identity. A shop redirect is only a success candidate; its query is discarded and no shop/card action is loaded. Rust preserves bounded provider cookie scope/expiry in a dedicated jar, independent of the guest client and WebView. Only email, display name, verification time and local status reach Svelte. Expiry clears the active profile; offline saved data stays explicitly cached.

Explicit Save/Unlock uses `RealSessionVault` in a separate version/purpose/alias/file. A process-owned coordinator, Activity leases, serialized Rust account mutations and request/native epochs fence late login, prompt and cleanup completions. The authenticated AES-GCM file contains provider cookies and the profile cache, without the password; supported strong-biometric authorization is required per save/unlock. Logout/Forget deletion continues after UI navigation and blocks another account operation until complete. Raw native storage bridge names are never public capabilities. Native screenshot/form-persistence controls and all biometric/file behavior still need device verification. See [authentication](authentication.md) and [account verification](account-verification.md).

The synthetic vault separates platform key/file/authentication adapters from a synchronized native state machine. Its generation fence rejects late biometric completions after cancellation or deletion. Internal operations accept no real credential and return no plaintext. `AccountVault` exposes status only and intentionally has no usable authorization path for frontend saves; the internal biometric adapter is preparation for controlled synthetic testing. See [authentication](authentication.md) and [security](security.md) for the record format, lifecycle and remaining release gates.

Provider session state remains process-local and serialized through opening/open/cleaning/closed states. Back navigates provider history and then closes the Activity. Close stops and destroys the view, requests cleanup and returns after the cookie callback succeeds or fails visibly. Cleanup generations reject obsolete callbacks; interception denies requests while closed or cleaning. Rotation uses Activity configuration handling. Process recreation closes the old flow rather than replaying website requests. No browser history or transaction is automatically restored.

**The Android architecture gate remains open.** An earlier debug APK establishes compilation/packaging only. View/Back/IME/rotation lifecycle, provider functionality, bridge exclusion, system bars, TalkBack, request interception, actual Keystore authorization and all website-storage cleanup require device validation. No Android device is currently connected. `WebStorage.deleteAllData()` has no completion callback and does not prove that service-worker/IndexedDB/cache artifacts are gone. Resolve this before account switching or persistent authentication; see [the Android API](<https://developer.android.com/reference/android/webkit/WebStorage#deleteAllData()>). The separate provider view is a privilege boundary, not a separate WebView profile or an incognito guarantee.
